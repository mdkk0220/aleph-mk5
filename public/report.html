3. 고정 검사 10개

작업 시작 전에 정했고, 이후 삭제·완화·기대값 변경이 0건입니다(저장소의 checks/ 변경 이력으로 확인).

ID입력관찰 가능한 기대값
T01이름 "A"로 저장목록에 "A"가 보이고 저장 실패 문구가 없음
T02이름을 비우고 저장"템플릿 1"이 보임
T03저장 후 새로고침목록에 남아 있음
T04A, B 저장 후 새로고침A, B가 이 순서로 2개
T05문구·가로·크기·색·비율을 정해 저장 → 바꿈 → 불러오기저장 당시 값으로 복원
T06A, B 저장 → A 삭제 → 새로고침B만 남음
T07문구를 비운 채 저장"(빈 문구)" 표시
T08이름에 공백만 입력"템플릿 1"이 보임
T09크기 최솟값 2, 최댓값 20으로 각각 저장 후 불러오기"희망 크기 2%", "희망 크기 20%"
T10저장소 값을 깨진 JSON으로 두고 새로고침빈 목록 안내가 보이고 화면이 정상

수정 전 6/10 → 작업자 1 종료 10/10 → 작업자 2 종료 10/10. 탭 5는 고정 검사 밖이라 별도 확인 4개(저장, 새로고침 유지, JSON 가져오기 유지, 깨진 JSON 거부)를 돌렸고, 수정 전에는 3개가 실패하고 수정 후에는 모두 통과했습니다.

4. 소스와 확인 방법

소스: github.com/mdkk0220/aleph-mk5 (최종 커밋 c79bcc8)

  1. 어디로 가나요: 이 보고서 주소를 시크릿 창에서 엽니다. 소스는 위 링크입니다.
  2. 3단계 이내 무엇을 하나요: ① 위 비교표를 봅니다 → ② 소스를 내려받아 npm install, npm run build → ③ checks/의 검사를 실행합니다.
  3. 무엇이 보이면 통과인가요: 비교표 숫자가 보이고, 검사 실행 마지막 줄에 PASS 10/10이 나옵니다.
  4. 안 될 때 무엇이 보이나요: 빌드 오류 메시지, 또는 검사 줄에 FAIL과 실패한 검사 ID(T01 등)가 나옵니다.

6. AI와 나의 판단

  1. AI에게 맡긴 일: 코드 읽기와 원인 찾기, 검사 10개 초안과 실행기 작성, 저장소 어댑터 구현, 인수인계 문서 작성, 결과 독립 검증.
  2. 직접 판단한 일: 고칠 기능 선택, 저장소와 프로젝트 이름 결정, 저장소 생성과 올리기, 다른 모델로 두 번째 작업자 선택, 태그가 가리킬 커밋 지정.
  3. AI 제안을 따르지 않은 일: 도구가 태그를 현재 main 기준으로 만들자고 제안했으나, 인수인계 문서의 버전 ID와 맞추려고 해당 커밋을 직접 지정했다.
